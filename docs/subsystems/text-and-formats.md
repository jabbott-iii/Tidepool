# Subsystem: `tidepool-text`, `tidepool-codec` and `tidepool-regex`

## `tidepool-text`

| Module | Provides |
| :- | :- |
| `rope` | Persistent B-tree rope of UTF-8 chunks (1–4 KiB); O(log n) edits, split, append and slice; O(1) `Clone` for snapshots; chunk and char iterators |
| `pos` | Byte offsets (canonical); char, UTF-16 and line conversions; line/column in bytes, UTF-16 or chars (LSP's encodings); extended grapheme cluster boundaries (UAX #29, tables from `cargo xtask ucd`) |
| `selection` | Multi-cursor `Selection`: one or more `Cursor { anchor, head }` (byte offsets), sorted and merged by one rule, with a primary; validated against a rope; mapped through change sets |
| `transaction` | `ChangeSet`: canonical byte-range replacements in the old text, each holding its new text as a `Rope`; apply, map positions, compose, invert. `Transaction`: a change set and the selection after it; `change_each` for multi-cursor commands |
| `history` | Undo tree that applies every step to the buffer's rope: branches kept, grouping by command (`GroupId`) and by time (coalescing kinds), saved-state markers through checkpoints |
| `encoding` | UTF-8, UTF-16 LE/BE with BOM, detected by BOM only; invalid UTF-8 or UTF-16 opens read-only and lossless |
| `file` | Load (with size threshold for large-file mode), atomic save (temp file in the same directory, fsync, rename, keep permissions, links followed), line-ending and trailing-newline preservation |

Invariants:

- Unchanged files save byte-for-byte identical.
- Every position conversion round-trips for every valid position.
- `undo` after any sequence of transactions restores the exact prior text.

### `rope` and `pos`

Positions follow ADR-0019; the Unicode data follows ADR-0018.

- **Structure.** Leaves of 1,024–4,096 bytes (built at 3,072), internal
  nodes of 8–16 children (the root 2–16), all leaves at one depth. Each
  parent keeps its children's bytes, chars, UTF-16 units and line breaks.
  `Clone` is O(1); an edit copies only the nodes on its path that a
  snapshot shares. `Rope` is `Send + Sync`.
- **Chunks** never split a character or a CR LF pair, so line breaks add
  up per chunk. They may split a grapheme cluster. Chunk sizes are not part
  of the API.
- **Positions** are byte offsets; ranges are byte ranges. A valid offset is
  a char boundary in `0..=len`, including the one between CR and LF.
- **Lines** end at LF, CR LF or a lone CR (LSP 3.17); VT, FF, NEL, LS and
  PS are ordinary characters. A text has one more line than line breaks:
  the empty text is one line, and a text ending in a break ends with an
  empty line.
- **Columns** of a line are its char boundaries from its start up to, not
  including, the next line's start (on the last line, up to the end),
  counted in `Unit::Byte`, `Utf16` or `Char` (LSP `utf-8`, `utf-16`,
  `utf-32`). So the offset between CR and LF is one column past the
  content. LSP cannot express it, and `lang` handles that (M6.7).
- **Errors.** Edits, slices, iterator constructors and conversions return
  `Result<_, TextError>` and change nothing on error; nothing panics on
  input. Total functions: `is_char_boundary`, `floor_char_boundary`,
  `ceil_char_boundary` and the grapheme queries. Messages hold numbers,
  never text; `Debug` shows sizes only.
- **Round trips.** Byte ↔ offset in each unit and byte ↔ line/column in
  each unit are bijections on valid positions;
  `byte_to_line(line_to_byte(l)) == l`; every invalid input gives its
  documented error.
- **Graphemes** follow UAX #29 (revision 47, Unicode 17.0.0) exactly, on
  `&str` and across chunks. Byte 0 and the length are boundaries, also of
  the empty text; iterating the empty text yields no clusters. Rules GB9c,
  GB11 and GB12/13 need left context. A query that meets one steps back in
  one pass that recovers each part of the rule state from its own pattern.
  - **Typical text** costs O(1) per query.
  - **A run of marks** costs O(1) per position.
  - **GB9c and GB11** are linear in the run of Extend and ZWJ characters
    before the position.
  - **GB12/13** are linear in the run of regional indicators. So repeated
    `next`/`prev` calls across one run of r indicators cost O(r²); to sweep,
    use the iterators.
  - **`next`/`prev`** are also linear in the distance to the boundary they
    return. On a rope, each step back adds a descent.
  - **Iterators** carry the state and step back at most once, at the first
    context rule; never from byte 0. So iterating is O(1) per char, and a
    `graphemes_in` window inside a run of marks costs only the window.
  - **No step back** passes a line break.
- **Tables.** `src/pos/grapheme/tables.rs` is generated by
  `cargo xtask ucd` from `ucd/17.0.0/`; never edit it by hand. A test
  checks that its Unicode version is `char::UNICODE_VERSION`.

### `selection`

Edits follow ADR-0020; positions follow ADR-0019.

- **Cursors** are `anchor` and `head` byte offsets; `anchor == head` is a
  caret, `head < anchor` is backward. Nothing here snaps to graphemes;
  commands do.
- **Normalizing** (every constructor, `transform`, `map`) sorts by start,
  then end.
  - Ranges merge when they share a byte.
  - A caret inside a range, or at either edge, joins it; where two ranges
    touch, it joins the earlier.
  - Equal carets become one.
  - Touching ranges stay apart, so adjacent matches stay separate.
  - A merged cursor spans its parts. It takes the primary's direction if
    the primary is a non-empty part, else that of its first non-empty part.
  - The primary is the cursor holding the old primary.
  - O(r) when already sorted.
- **Invariants:** at least one cursor; starts strictly increase; neighbours
  touch only when both are non-empty; the primary index is in range.
- **Validating** checks each cursor's start, then its end, in order, in one
  walk.
- **Mapping:**
  - carets map with the caller's `Assoc`;
  - a range maps its start `After` and its end `Before`, so it never grows
    from text inserted at its edges;
  - a range whose ends meet or cross becomes a caret where its start maps
    with the caret `Assoc`.

  The result needs no sort: O(k + r).

### `transaction`

- **Change sets** are sorted replacements in old-text byte offsets, each
  holding its new text as a `Rope`. At least one kept byte separates any
  two, and none does nothing, so `==` is structural. `Clone` is O(1);
  `Debug` shows sizes only.
- **Building** takes the text, then:
  - checks each range as `Rope::replace` checks it, in input order;
  - drops empty edits;
  - sorts the edits stably by start, then end;
  - refuses an edit that starts before the previous ends
    (`OverlappingEdits`), and a result over `isize::MAX` bytes (`TooLong`).

  Touching edits merge. Inserts at one offset keep their order and come
  before an edit that starts there (LSP).
- **Applying** checks the length and every replacement's ends before
  changing anything.
  - Fewer than 64 replacements, or more than 4 KiB of old and new text per
    replacement, go one by one from the last, sharing large texts.
  - Otherwise the text is rebuilt in one pass, which shares nothing with
    the old text. The measured break-even is about 6 KB per replacement: a
    10,000-caret keystroke on a 400 KB file takes about 1–1.5 ms instead of
    about 95 ms.
- **Inverting** needs the text before; inverting the deletion of a whole
  text is O(log n).
- **Composing** merges both sets in one pass, so an Insert session stays one
  replacement per cursor.
- **Mapping** a position:
  - kept text shifts;
  - the start and end of a replaced range go to the start and end of its
    new text;
  - at a pure insert, or strictly inside a replaced range, `Before` goes to
    the new text's start and `After` to its end.

  Mapping is monotone, and char boundaries map to char boundaries.
- **Not laws:**
  - through a composed set, positions at or inside its replacements may map
    differently than step by step;
  - merging touching edits forgets the seam between them.
- **Laws** (property-tested):
  - invert undoes, and is an involution;
  - compose applies both, is associative, has the identity as unit, and
    `(a∘b)⁻¹ = b⁻¹∘a⁻¹`;
  - `c∘c⁻¹` is the identity in effect only.
- **For LSP**, send `changes()` last first, converting `old` on
  `Step.before`. **For syntax**, re-lex the `new` ranges.
- **Transactions** pair a change set with the selection after it.
  `change_each`:
  - validates the selection, then calls a closure once per cursor;
  - checks every edit it returns, including one that does nothing, which
    then counts as no edit;
  - after a stable sort by range, merges overlapping deletions, and an
    edit with the same range and text as the edit kept just before it.
    So identical deletions and replacements always merge, but among pure
    inserts at one offset only consecutive identical ones do: cursors
    inserting "a", "b", "a" there insert all three. Other overlaps are
    errors;
  - maps cursors through the edits themselves, so seams are kept;
  - places each cursor that edited (`Map`, `Start`, `End`, `Select`).

### `history`

- **Revisions** form a tree numbered in creation order; `root()` is the
  oldest. Each keeps:
  - its change from its parent, and the inverse;
  - the selections before and after;
  - a time and a grouping tag.

  Nothing is pruned in v1.
- **Every buffer edit goes through the history.** `commit`, `undo`, `redo`
  and `jump_to`:
  - take the buffer's rope;
  - refuse any rope that is not the tree the history last produced
    (`HistoryMismatch`);
  - change both or neither;
  - return a `Step`: the text before, the change sets applied in order (one
    per hop), the selection to show, and the revision now current.
- **Grouping:**
  - `Group::New` always starts a revision.
  - `Group::Command(id)` joins the current revision if it is open and was
    made with the same id: a vim command, Insert session or macro replay,
    or an agent proposal. Ids come from `GroupId::fresh()` and are unique
    in the process.
  - `Group::Coalesce { kind, window }` joins one of the same kind, last
    committed into within `window`, if the cursors did not move.

  Undo, redo, jumps, `seal` and `checkpoint` close the current revision;
  moves that do nothing do not. A commit that changes nothing records
  nothing. A group of K scattered edits costs O(K log K).
- **Undo** goes to the parent and restores the selection before.
- **Redo** goes to the child created or visited last.
- **Committing after an undo** starts a branch and keeps the old one.
- **`jump_to`** reaches any revision through the lowest common ancestor.
  The path from the root to the current revision always runs through each
  parent's last child.
- **Saved state:**
  - `checkpoint()` seals the revision and returns it with its text, when a
    save starts;
  - `mark_saved(&checkpoint)` records the save when it succeeds;
  - saves of one buffer are serialized;
  - `is_modified` is false exactly at the saved revision, on any branch.

  Revision ids and checkpoints belong to one history; one from another
  history is not detected while its number is in range.
- **Time** is a `std::time::Instant` from the caller.

### `encoding`

Line breaks are text (ADR-0019): nothing here changes them.

- **Formats.** An `Encoding` is UTF-8, UTF-16 LE or UTF-16 BE; a `Format`
  is an encoding and whether its BOM comes first. New files are UTF-8
  without a BOM (`Format::UTF8`, the default).
- **Detection** is by BOM only: `EF BB BF`, `FF FE` or `FE FF`, and
  anything else is UTF-8 without one. No heuristics: no Latin-1, no UTF-16
  without a BOM (it reads as UTF-8), no UTF-32 (`FF FE 00 00` reads as
  UTF-16 LE and U+0000). The BOM is not part of the text.
- **Decoding never fails.**
  - UTF-8: one U+FFFD per maximal subpart of an ill-formed sequence
    (Unicode §3.9), as `String::from_utf8_lossy`.
  - UTF-16: one U+FFFD per unpaired surrogate, and one for an odd last
    byte.
- **Lossless.** `Decoded` keeps each run of replaced bytes, its range in
  the text and its original bytes, and touching runs merge. So
  `original_bytes` rebuilds the input exactly, BOM included, for every
  input. A run costs its bytes (at most three for each U+FFFD) and a head
  of about three more (LEB128), so a binary file's runs take at most about
  twice what its U+FFFDs take in the rope; a long run costs one head.
- **Read-only.** A text with any replacement has no save format:
  `Decoded::format` is `None`.
- **Streaming.** `Decoder::push` takes pieces of any size, and builds the
  rope with a `RopeBuilder`. A BOM, a UTF-8 sequence or a surrogate pair may
  be split across pieces: the result is the same however the input is
  split. `decode` is one push.
- **Encoding** writes a rope to any `io::Write` one chunk at a time, BOM
  first if the format has one. Text decoded without a replacement
  re-encodes in its detected format to the input, byte for byte. Without a
  BOM, a text whose first character is written as a BOM (U+FEFF, or U+FFFE
  in UTF-16, the other byte order's) reads back in that BOM's format,
  without the character.

### `file`

Saving follows ADR-0025.

- **Loading** (`load`):
  - follows links, as `std` does;
  - only a regular file loads. A directory, FIFO, socket or device is
    `NotRegularFile`, checked from metadata before opening, so a FIFO never
    blocks;
  - reads 64 KiB blocks into a `Decoder`.

  `Loaded` has the text, the format (`None` exactly when bytes were
  replaced: then it is read-only), the detected format, the decoding with
  its replaced runs, the line endings, the trailing break, the bytes read
  and `is_large`.
- **Line endings and the trailing newline** are reported, never changed:
  the rope holds the text as it was, so an unchanged file saves byte for
  byte. `LineEndings` counts LF, CR LF and CR breaks. `dominant` is the
  most common; LF wins ties, then CR LF, so no breaks gives LF.
- **Large** means more than `LARGE_FILE_BYTES` (16 MiB) read. Large-file
  mode is the editor's (`docs/subsystems/editor.md`): a large file is not
  read-only here.
- **Saving** (`save(path, &Rope, Format)`) is atomic:
  1. follows the chain of symbolic links at the path, at most 40 (else
     `TooManyLinks`), a relative link from its own directory. A missing
     target is created;
  2. an existing target must be a regular file that the user may write,
     tested by opening it for writing without creating or truncating it.
     Otherwise `NotRegularFile` or `NotWritable`, and nothing changes;
  3. creates a temp file in the target's directory with `create_new`,
     retrying another name: `.tidepool-save-<pid>-<count>-<time>.tmp`
     (`TEMP_PREFIX`), of fixed length. For an existing target it starts
     with mode 0600 on Unix, through the one `cfg(unix)` in `text`'s
     library; for a new file, `std`'s default mode;
  4. writes through a buffer, gives the temp file the target's permissions
     (on Unix without setuid and setgid, as a write in place would lose
     them, through the same `cfg(unix)`), and syncs it;
  5. renames it over the target, so links stay links;
  6. syncs the directory. Where the directory cannot be opened (always on
     Windows, where `std` cannot open one), or the file system refuses to
     sync one (`EINVAL` or `ENOTSUP`, as VirtualBox shared folders do), this
     is skipped. If the sync fails otherwise, the error is `Io` at
     `SyncDirectory` and the new text is already in place.

  An error before the rename removes the temp file and leaves the target
  untouched. A crash leaves the temp file behind.
- **A rename makes a new file:** it splits a hard link, gives the file the
  saver's owner and group on Unix (even when only the group differs) and
  the access list its directory passes on (a default POSIX ACL on Linux,
  the inherited ACL on Windows), and drops extended attributes.
  `workspace::buffers` checks the link count, owner and group first (M4.3).
- **Errors** name the step that failed (`FileStep`) and carry the
  operating system's error as their source. Messages hold no path and no
  text.
- **Callers** load and save on workers, and serialize the saves of one
  file (`History::checkpoint` and `mark_saved`).

## `tidepool-codec`

All parsers take a `Limits` struct (depth, string bytes, entries,
decompressed size, expansion ratio) and return errors with an offset or a
line and column. None of them panic on input.

| Module | Supports | Used by |
| :- | :- | :- |
| `json` | RFC 8259, strict by default; JSONC (comments, one trailing comma) as an option; writer (compact, pretty). Subset: see `json` below | LSP/DAP/TAP, cargo diagnostics, `cargo metadata`, `xtask` |
| `toml` | TOML 1.0; a comment- and order-preserving document model for files Tidepool writes back | Settings, keymaps, themes, packs, descriptors, `Cargo.toml` |
| `xml` | Well-formed XML 1.0 without DTDs or external entities (none are fetched or expanded) | `AndroidManifest.xml`, plist |
| `plist` | XML property lists (read/write) | `Info.plist`, `ExportOptions.plist`, entitlements |
| `yaml` | A documented YAML 1.2 subset for highlighting and validation (aliases with an expansion limit; no custom tags) | Viewing YAML files |
| `csv`, `ini` | RFC 4180 CSV; INI | Viewers |
| `inflate`, `deflate` | RFC 1951 (port Nadir's inflate) | ZIP, PNG |
| `zip` | Read and write, stored and deflated entries, ZIP64 read, alignment for stored entries, path-traversal rejection | APK/AAB/IPA inspection and assembly |
| `png` | Decode all color types and depths (port Nadir's decoder) | Image viewer, icons |
| `qoi` | Encode and decode | Golden frames |

### `json`

`parse(&str, Dialect, Limits)` and `parse_bytes(&[u8], Dialect, Limits)`
return a `Value`; `to_string_compact` and `to_string_pretty` write one. The
module documentation in `crates/codec/src/json.rs` is authoritative; this is
its summary.

`Dialect::Json`, the default, is RFC 8259 with these choices where the RFC
leaves room:

- Exactly one value, of any kind, at the top level; anything but whitespace
  after it is an error. Whitespace is space, tab, LF and CR only.
- The input must be UTF-8 everywhere, strings included. `parse_bytes`
  rejects anything else (`InvalidUtf8`, at the first bad byte) and never
  repairs it.
- Only a leading byte-order mark (U+FEFF) is skipped. Anywhere else outside
  a string it is an error; inside a string it is an ordinary character.
- Escapes are the RFC's: `\" \\ \/ \b \f \n \r \t` and `\uXXXX` (hex in
  either case). A surrogate pair written as two `\u` escapes is one
  character. A lone surrogate (a high one not followed by a `\u` low one, or
  a low one alone) is rejected (`LoneSurrogate`), never replaced. Raw
  U+0000 to U+001F in a string is rejected (`ControlCharacter`).
- Repeated object names are kept: every member stays, in document order, in
  `Value::Object(Vec<(String, Value)>)`, and `Value::get` returns the last,
  as `JSON.parse` does. Names compare exactly: decoded, case-sensitive, no
  Unicode normalization.
- Numbers follow the RFC grammar (no leading zeros, `+`, `.5`, `5.`, hex,
  `NaN` or `Infinity`) and are stored as a `Number`:
  - no fraction or exponent: an exact `u64` (0 and up) or `i64` (below 0)
  - a fraction or exponent, `-0`, or an integer outside both types: the
    nearest `f64`; digits beyond what it holds are lost
  - a magnitude too large for an `f64` (`1e400`) is an error
    (`NumberOutOfRange`); one too small (`1e-400`) underflows to zero
  - never NaN or infinite, so `Number` is `Eq` and the writers cannot fail;
    `2` and `2.0` are different numbers, `0.0` and `-0.0` are equal, and
    the integer accessors never convert a float

`Dialect::Jsonc` accepts all of that and adds exactly two things:

- Comments wherever whitespace may appear: `//` to the next LF or CR, and
  `/* */`, which does not nest; an unterminated one is an error. Comments
  are not kept in the `Value`.
- One trailing comma after the last entry of a non-empty array or object
  (`[1,]`, `{"a":1,}`); not `[,]`, not `[1,,]`, not after the top-level
  value.

Single quotes, unquoted keys and the other JSON5 extensions are errors in
both dialects. In `Dialect::Json` a comment is `CommentNotAllowed` and a
trailing comma is `TrailingCommaNotAllowed`.

Errors: every failure is `CodecError::Json { offset, line, column, kind }`
with a `json::ErrorKind`; the parser never panics.

- `offset`: bytes into the input as given, counting a leading byte-order
  mark.
- `line`: from 1, counted at each LF (CR-LF counts once).
- `column`: from 1, in Unicode scalar values, not bytes; a leading
  byte-order mark is not counted.
- `UnexpectedEnd` is at the end of the input, except when the input ends
  inside a string, block comment or escape sequence: then it points at
  where that construct starts, and `expected` says so. `InputTooLarge`
  points at the character that holds the first byte past the limit.

`Limits`, each checked before the memory it guards is allocated (override
fields with `Limits { max_input_bytes: n, ..Limits::DEFAULT }`):

| Field | Default | Bounds |
| :- | :- | :- |
| `max_input_bytes` | 64 MiB | Input length; checked first (in `parse_bytes`, before UTF-8 validation) |
| `max_depth` | 128 | Array and object nesting (a scalar is depth 0, `[[1]]` is 2) |
| `max_string_bytes` | 16 MiB | One string or key, in UTF-8 bytes after escapes are decoded |
| `max_number_bytes` | 1,024 | One number's text (sign, digits, point, exponent) |
| `max_entries` | 1,000,000 | Elements or members of one array or object, not of the whole document |

Memory and stack:

- The parser keeps its own stack on the heap and takes a failed tree apart
  without recursing, so no depth limit can overflow the thread's stack
  while parsing. Dropping, cloning, comparing, `Debug` and writing a `Value`
  do recurse once per level, so keep `max_depth` in the hundreds.
- A parsed tree takes at most 16 bytes of heap per byte of text, plus a
  constant and a little working memory while parsing: a `Value` is 32 bytes
  and needs at least 2 bytes of text (`0,`), and containers are allocated
  at exactly their size. With glibc's per-allocation overhead, the worst
  documents measured (`[[0]],` repeated) grow the process by about 23 times
  their text; typical ones take 2 to 4 times (`cargo metadata` about 3). At
  the default `max_input_bytes` the tree is capped at 1 GiB, about 1.5 GiB
  with glibc.

Writing:

- Both writers emit strict JSON (no comments, no trailing commas) with
  members in stored order, repeated names included, and escape only `"`,
  `\` and U+0000 to U+001F. Integers are written as their digits; floats as
  the shortest form that reads back as the same `f64`, always with a `.` or
  an exponent (`1e3` is written `1000.0`).
- Pretty output indents two spaces per level, writes `": "` after names,
  keeps empty containers as `[]` and `{}`, and has no trailing newline.
- Output reads back as an equal value if it fits the `Limits` it is read
  with; it can be longer than the text it was parsed from.
- Pretty output of a value nested `d` deep is at most `2d + 2` times its
  compact size. Values shaped for it (`[[[0]]],` repeated) reach about 236
  times at depth 128, so a 64 MiB document can pretty-print to about 15 GiB.
  Bound the depth or compact size of an outside value before pretty-printing
  it.

## `tidepool-regex`

- Parser → NFA → Pike VM simulation; linear time in input length for every
  pattern. No backreferences or lookaround (documented; vim mode reports
  the difference).
- Unicode classes for general categories and scripts used by language
  packs; case-insensitive matching with simple case folding.
- Literal prefix acceleration for search.

## Tests

- `text`:
  - property tests against a `String` model (≥ 10,000 random edit
    sequences, with tiny chunks in unit tests and real sizes in integration
    tests);
  - conversion round-trips at every position in every unit (tiny chunks),
    and near every seam and sampled elsewhere at real sizes;
  - grapheme conformance with every case of `GraphemeBreakTest.txt`, also
    split across chunks;
  - a reference reading of the rules, and the Unicode version test;
  - undo, redo and jumps against a model that keeps every revision's text.
    The model covers random commits with every grouping, long command
    groups, branches, saved markers and errors, with the apply path forced
    at random. The tests check that:
    - undo restores the first text exactly;
    - every revision is reachable with its exact text;
    - every refused operation changes nothing;
  - change-set laws and mapping against a `String` model, and selection
    invariants after every operation;
  - decoding random bytes biased toward near-valid UTF-8 and UTF-16, against
    `String::from_utf8_lossy` and `char::decode_utf16`: lossless for every
    input, the same however it is split, and valid input re-encodes to
    itself;
  - file round-trips byte for byte: UTF-8 with and without a BOM, UTF-16 LE
    and BE, LF, CR LF, lone CR, mixed endings, no trailing newline, the
    empty file; invalid files load read-only; a simulated crash between
    write and rename and a failed write leave the original; refused saves
    change nothing; the large-file threshold; on Unix, modes and links.
- `codec`: RFC 8259 JSON cases, TOML 1.0 compliance cases, ZIP files
  produced by the `zip` command-line tool and by Android and Apple tools,
  hand-made vectors for inflate edge cases (stored, fixed and dynamic
  blocks, back-references at the window edge); every module is a fuzz
  target with a seed corpus.
- `regex`: conformance table; pathological patterns (`(a*)*b` on long
  inputs) finish in linear time.
