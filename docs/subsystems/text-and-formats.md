# Subsystem: `tidepool-text`, `tidepool-codec` and `tidepool-regex`

## `tidepool-text`

| Module | Provides |
| :- | :- |
| `rope` | Persistent B-tree rope of UTF-8 chunks (1–4 KiB); O(log n) edits, split, append and slice; O(1) `Clone` for snapshots; chunk and char iterators |
| `pos` | Byte offsets (canonical); char, UTF-16 and line conversions; line/column in bytes, UTF-16 or chars (LSP's encodings); extended grapheme cluster boundaries (UAX #29, tables from `cargo xtask ucd`) |
| `selection` | Multi-cursor `Selection`: one or more `Cursor { anchor, head }` (byte offsets), sorted and merged by one rule, with a primary; validated against a rope; mapped through change sets |
| `transaction` | `ChangeSet`: canonical byte-range replacements in the old text, each holding its new text as a `Rope`; apply, map positions, compose, invert. `Transaction`: a change set and the selection after it; `change_each` for multi-cursor commands |
| `history` | Undo tree that applies every step to the buffer's rope: branches kept, grouping by command (`GroupId`) and by time (coalescing kinds), saved-state markers through checkpoints |
| `encoding` | UTF-8, UTF-16 LE/BE with BOM, detected by BOM only; invalid UTF-8 or UTF-16 opens read-only and lossless |
| `file` | Load (with size threshold for large-file mode), atomic save (temp file in the same directory, fsync, rename, keep permissions, links followed), line-ending and trailing-newline preservation |

Invariants:

- Unchanged files save byte-for-byte identical.
- Every position conversion round-trips for every valid position.
- `undo` after any sequence of transactions restores the exact prior text.

### `rope` and `pos`

Positions follow ADR-0019; the Unicode data follows ADR-0018.

- **Structure.** Leaves of 1,024–4,096 bytes (built at 3,072), internal
  nodes of 8–16 children (the root 2–16), all leaves at one depth. Each
  parent keeps its children's bytes, chars, UTF-16 units and line breaks.
  `Clone` is O(1); an edit copies only the nodes on its path that a
  snapshot shares. `Rope` is `Send + Sync`.
- **Chunks** never split a character or a CR LF pair, so line breaks add
  up per chunk. They may split a grapheme cluster. Chunk sizes are not part
  of the API.
- **Positions** are byte offsets; ranges are byte ranges. A valid offset is
  a char boundary in `0..=len`, including the one between CR and LF.
- **Lines** end at LF, CR LF or a lone CR (LSP 3.17); VT, FF, NEL, LS and
  PS are ordinary characters. A text has one more line than line breaks:
  the empty text is one line, and a text ending in a break ends with an
  empty line.
- **Columns** of a line are its char boundaries from its start up to, not
  including, the next line's start (on the last line, up to the end),
  counted in `Unit::Byte`, `Utf16` or `Char` (LSP `utf-8`, `utf-16`,
  `utf-32`). So the offset between CR and LF is one column past the
  content. LSP cannot express it, and `lang` handles that (M6.7).
- **Errors.** Edits, slices, iterator constructors and conversions return
  `Result<_, TextError>` and change nothing on error; nothing panics on
  input. Total functions: `is_char_boundary`, `floor_char_boundary`,
  `ceil_char_boundary` and the grapheme queries. Messages hold numbers,
  never text; `Debug` shows sizes only.
- **Round trips.** Byte ↔ offset in each unit and byte ↔ line/column in
  each unit are bijections on valid positions;
  `byte_to_line(line_to_byte(l)) == l`; every invalid input gives its
  documented error.
- **Graphemes** follow UAX #29 (revision 47, Unicode 17.0.0) exactly, on
  `&str` and across chunks. Byte 0 and the length are boundaries, also of
  the empty text; iterating the empty text yields no clusters. Rules GB9c,
  GB11 and GB12/13 need left context. A query that meets one steps back in
  one pass that recovers each part of the rule state from its own pattern.
  - **Typical text** costs O(1) per query.
  - **A run of marks** costs O(1) per position.
  - **GB9c and GB11** are linear in the run of Extend and ZWJ characters
    before the position.
  - **GB12/13** are linear in the run of regional indicators. So repeated
    `next`/`prev` calls across one run of r indicators cost O(r²); to sweep,
    use the iterators.
  - **`next`/`prev`** are also linear in the distance to the boundary they
    return. On a rope, each step back adds a descent.
  - **Iterators** carry the state and step back at most once, at the first
    context rule; never from byte 0. So iterating is O(1) per char, and a
    `graphemes_in` window inside a run of marks costs only the window.
  - **No step back** passes a line break.
- **Tables.** `src/pos/grapheme/tables.rs` is generated by
  `cargo xtask ucd` from `ucd/17.0.0/`; never edit it by hand. A test
  checks that its Unicode version is `char::UNICODE_VERSION`.

### `selection`

Edits follow ADR-0020; positions follow ADR-0019.

- **Cursors** are `anchor` and `head` byte offsets; `anchor == head` is a
  caret, `head < anchor` is backward. Nothing here snaps to graphemes;
  commands do.
- **Normalizing** (every constructor, `transform`, `map`) sorts by start,
  then end.
  - Ranges merge when they share a byte.
  - A caret inside a range, or at either edge, joins it; where two ranges
    touch, it joins the earlier.
  - Equal carets become one.
  - Touching ranges stay apart, so adjacent matches stay separate.
  - A merged cursor spans its parts. It takes the primary's direction if
    the primary is a non-empty part, else that of its first non-empty part.
  - The primary is the cursor holding the old primary.
  - O(r) when already sorted.
- **Invariants:** at least one cursor; starts strictly increase; neighbours
  touch only when both are non-empty; the primary index is in range.
- **Validating** checks each cursor's start, then its end, in order, in one
  walk.
- **Mapping:**
  - carets map with the caller's `Assoc`;
  - a range maps its start `After` and its end `Before`, so it never grows
    from text inserted at its edges;
  - a range whose ends meet or cross becomes a caret where its start maps
    with the caret `Assoc`.

  The result needs no sort: O(k + r).

### `transaction`

- **Change sets** are sorted replacements in old-text byte offsets, each
  holding its new text as a `Rope`. At least one kept byte separates any
  two, and none does nothing, so `==` is structural. `Clone` is O(1);
  `Debug` shows sizes only.
- **Building** takes the text, then:
  - checks each range as `Rope::replace` checks it, in input order;
  - drops empty edits;
  - sorts the edits stably by start, then end;
  - refuses an edit that starts before the previous ends
    (`OverlappingEdits`), and a result over `isize::MAX` bytes (`TooLong`).

  Touching edits merge. Inserts at one offset keep their order and come
  before an edit that starts there (LSP).
- **Applying** checks the length and every replacement's ends before
  changing anything.
  - Fewer than 64 replacements, or more than 4 KiB of old and new text per
    replacement, go one by one from the last, sharing large texts.
  - Otherwise the text is rebuilt in one pass, which shares nothing with
    the old text. The measured break-even is about 6 KB per replacement: a
    10,000-caret keystroke on a 400 KB file takes about 1–1.5 ms instead of
    about 95 ms.
- **Inverting** needs the text before; inverting the deletion of a whole
  text is O(log n).
- **Composing** merges both sets in one pass, so an Insert session stays one
  replacement per cursor.
- **Mapping** a position:
  - kept text shifts;
  - the start and end of a replaced range go to the start and end of its
    new text;
  - at a pure insert, or strictly inside a replaced range, `Before` goes to
    the new text's start and `After` to its end.

  Mapping is monotone, and char boundaries map to char boundaries.
- **Not laws:**
  - through a composed set, positions at or inside its replacements may map
    differently than step by step;
  - merging touching edits forgets the seam between them.
- **Laws** (property-tested):
  - invert undoes, and is an involution;
  - compose applies both, is associative, has the identity as unit, and
    `(a∘b)⁻¹ = b⁻¹∘a⁻¹`;
  - `c∘c⁻¹` is the identity in effect only.
- **For LSP**, send `changes()` last first, converting `old` on
  `Step.before`. **For syntax**, re-lex the `new` ranges.
- **Transactions** pair a change set with the selection after it.
  `change_each`:
  - validates the selection, then calls a closure once per cursor;
  - checks every edit it returns, including one that does nothing, which
    then counts as no edit;
  - after a stable sort by range, merges overlapping deletions, and an
    edit with the same range and text as the edit kept just before it.
    So identical deletions and replacements always merge, but among pure
    inserts at one offset only consecutive identical ones do: cursors
    inserting "a", "b", "a" there insert all three. Other overlaps are
    errors;
  - maps cursors through the edits themselves, so seams are kept;
  - places each cursor that edited (`Map`, `Start`, `End`, `Select`).

### `history`

- **Revisions** form a tree numbered in creation order; `root()` is the
  oldest. Each keeps:
  - its change from its parent, and the inverse;
  - the selections before and after;
  - a time and a grouping tag.

  Nothing is pruned in v1.
- **Every buffer edit goes through the history.** `commit`, `undo`, `redo`
  and `jump_to`:
  - take the buffer's rope;
  - refuse any rope that is not the tree the history last produced
    (`HistoryMismatch`);
  - change both or neither;
  - return a `Step`: the text before, the change sets applied in order (one
    per hop), the selection to show, and the revision now current.
- **Grouping:**
  - `Group::New` always starts a revision.
  - `Group::Command(id)` joins the current revision if it is open and was
    made with the same id: a vim command, Insert session or macro replay,
    or an agent proposal. Ids come from `GroupId::fresh()` and are unique
    in the process.
  - `Group::Coalesce { kind, window }` joins one of the same kind, last
    committed into within `window`, if the cursors did not move.

  Undo, redo, jumps, `seal` and `checkpoint` close the current revision;
  moves that do nothing do not. A commit that changes nothing records
  nothing. A group of K scattered edits costs O(K log K).
- **Undo** goes to the parent and restores the selection before.
- **Redo** goes to the child created or visited last.
- **Committing after an undo** starts a branch and keeps the old one.
- **`jump_to`** reaches any revision through the lowest common ancestor.
  The path from the root to the current revision always runs through each
  parent's last child.
- **Saved state:**
  - `checkpoint()` seals the revision and returns it with its text, when a
    save starts;
  - `mark_saved(&checkpoint)` records the save when it succeeds;
  - saves of one buffer are serialized;
  - `is_modified` is false exactly at the saved revision, on any branch.

  Revision ids and checkpoints belong to one history; one from another
  history is not detected while its number is in range.
- **Time** is a `std::time::Instant` from the caller.

### `encoding`

Line breaks are text (ADR-0019): nothing here changes them.

- **Formats.** An `Encoding` is UTF-8, UTF-16 LE or UTF-16 BE; a `Format`
  is an encoding and whether its BOM comes first. New files are UTF-8
  without a BOM (`Format::UTF8`, the default).
- **Detection** is by BOM only: `EF BB BF`, `FF FE` or `FE FF`, and
  anything else is UTF-8 without one. No heuristics: no Latin-1, no UTF-16
  without a BOM (it reads as UTF-8), no UTF-32 (`FF FE 00 00` reads as
  UTF-16 LE and U+0000). The BOM is not part of the text.
- **Decoding never fails.**
  - UTF-8: one U+FFFD per maximal subpart of an ill-formed sequence
    (Unicode §3.9), as `String::from_utf8_lossy`.
  - UTF-16: one U+FFFD per unpaired surrogate, and one for an odd last
    byte.
- **Lossless.** `Decoded` keeps each run of replaced bytes, its range in
  the text and its original bytes, and touching runs merge. So
  `original_bytes` rebuilds the input exactly, BOM included, for every
  input. A run costs its bytes (at most three for each U+FFFD) and a head
  of about three more (LEB128), so a binary file's runs take at most about
  twice what its U+FFFDs take in the rope; a long run costs one head.
- **Read-only.** A text with any replacement has no save format:
  `Decoded::format` is `None`.
- **Streaming.** `Decoder::push` takes pieces of any size, and builds the
  rope with a `RopeBuilder`. A BOM, a UTF-8 sequence or a surrogate pair may
  be split across pieces: the result is the same however the input is
  split. `decode` is one push.
- **Encoding** writes a rope to any `io::Write` one chunk at a time, BOM
  first if the format has one. Text decoded without a replacement
  re-encodes in its detected format to the input, byte for byte. Without a
  BOM, a text whose first character is written as a BOM (U+FEFF, or U+FFFE
  in UTF-16, the other byte order's) reads back in that BOM's format,
  without the character.

### `file`

Saving follows ADR-0025.

- **Loading** (`load`):
  - follows links, as `std` does;
  - only a regular file loads. A directory, FIFO, socket or device is
    `NotRegularFile`, checked from metadata before opening, so a FIFO never
    blocks;
  - reads 64 KiB blocks into a `Decoder`.

  `Loaded` has the text, the format (`None` exactly when bytes were
  replaced: then it is read-only), the detected format, the decoding with
  its replaced runs, the line endings, the trailing break, the bytes read
  and `is_large`.
- **Line endings and the trailing newline** are reported, never changed:
  the rope holds the text as it was, so an unchanged file saves byte for
  byte. `LineEndings` counts LF, CR LF and CR breaks. `dominant` is the
  most common; LF wins ties, then CR LF, so no breaks gives LF.
- **Large** means more than `LARGE_FILE_BYTES` (16 MiB) read. Large-file
  mode is the editor's (`docs/subsystems/editor.md`): a large file is not
  read-only here.
- **Saving** (`save(path, &Rope, Format)`) is atomic:
  1. follows the chain of symbolic links at the path, at most 40 (else
     `TooManyLinks`), a relative link from its own directory. A missing
     target is created;
  2. an existing target must be a regular file that the user may write,
     tested by opening it for writing without creating or truncating it.
     Otherwise `NotRegularFile` or `NotWritable`, and nothing changes;
  3. creates a temp file in the target's directory with `create_new`,
     retrying another name: `.tidepool-save-<pid>-<count>-<time>.tmp`
     (`TEMP_PREFIX`), of fixed length. For an existing target it starts
     with mode 0600 on Unix, through the one `cfg(unix)` in `text`'s
     library; for a new file, `std`'s default mode;
  4. writes through a buffer, gives the temp file the target's permissions
     (on Unix without setuid and setgid, as a write in place would lose
     them, through the same `cfg(unix)`), and syncs it;
  5. renames it over the target, so links stay links;
  6. syncs the directory. Where the directory cannot be opened (always on
     Windows, where `std` cannot open one), or the file system refuses to
     sync one (`EINVAL` or `ENOTSUP`, as VirtualBox shared folders do), this
     is skipped. If the sync fails otherwise, the error is `Io` at
     `SyncDirectory` and the new text is already in place.

  An error before the rename removes the temp file and leaves the target
  untouched. A crash leaves the temp file behind.
- **A rename makes a new file:** it splits a hard link, gives the file the
  saver's owner and group on Unix (even when only the group differs) and
  the access list its directory passes on (a default POSIX ACL on Linux,
  the inherited ACL on Windows), and drops extended attributes.
  `workspace::buffers` checks the link count, owner and group first (M4.3).
- **Errors** name the step that failed (`FileStep`) and carry the
  operating system's error as their source. Messages hold no path and no
  text.
- **Callers** load and save on workers, and serialize the saves of one
  file (`History::checkpoint` and `mark_saved`).

### `json`

`parse(&str, Dialect, Limits)` and `parse_bytes(&[u8], Dialect, Limits)`
return a `Value`; `to_string_compact` and `to_string_pretty` write one. The
module documentation in `crates/codec/src/json.rs` is authoritative; this is
its summary.

`Dialect::Json`, the default, is RFC 8259 with these choices where the RFC
leaves room:

- Exactly one value, of any kind, at the top level; anything but whitespace
  after it is an error. Whitespace is space, tab, LF and CR only.
- The input must be UTF-8 everywhere, strings included. `parse_bytes`
  rejects anything else (`InvalidUtf8`, at the first bad byte) and never
  repairs it.
- Only a leading byte-order mark (U+FEFF) is skipped. Anywhere else outside
  a string it is an error; inside a string it is an ordinary character.
- Escapes are the RFC's: `\" \\ \/ \b \f \n \r \t` and `\uXXXX` (hex in
  either case). A surrogate pair written as two `\u` escapes is one
  character. A lone surrogate (a high one not followed by a `\u` low one, or
  a low one alone) is rejected (`LoneSurrogate`), never replaced. Raw
  U+0000 to U+001F in a string is rejected (`ControlCharacter`).
- Repeated object names are kept: every member stays, in document order, in
  `Value::Object(Vec<(String, Value)>)`, and `Value::get` returns the last,
  as `JSON.parse` does. Names compare exactly: decoded, case-sensitive, no
  Unicode normalization.
- Numbers follow the RFC grammar (no leading zeros, `+`, `.5`, `5.`, hex,
  `NaN` or `Infinity`) and are stored as a `Number`:
  - no fraction or exponent: an exact `u64` (0 and up) or `i64` (below 0)
  - a fraction or exponent, `-0`, or an integer outside both types: the
    nearest `f64`; digits beyond what it holds are lost
  - a magnitude too large for an `f64` (`1e400`) is an error
    (`NumberOutOfRange`); one too small (`1e-400`) underflows to zero
  - never NaN or infinite, so `Number` is `Eq` and the writers cannot fail;
    `2` and `2.0` are different numbers, `0.0` and `-0.0` are equal, and
    the integer accessors never convert a float

`Dialect::Jsonc` accepts all of that and adds exactly two things:

- Comments wherever whitespace may appear: `//` to the next LF or CR, and
  `/* */`, which does not nest; an unterminated one is an error. Comments
  are not kept in the `Value`.
- One trailing comma after the last entry of a non-empty array or object
  (`[1,]`, `{"a":1,}`); not `[,]`, not `[1,,]`, not after the top-level
  value.

Single quotes, unquoted keys and the other JSON5 extensions are errors in
both dialects. In `Dialect::Json` a comment is `CommentNotAllowed` and a
trailing comma is `TrailingCommaNotAllowed`.

Errors: every failure is `CodecError::Json { offset, line, column, kind }`
with a `json::ErrorKind`; the parser never panics.

- `offset`: bytes into the input as given, counting a leading byte-order
  mark.
- `line`: from 1, counted at each LF (CR-LF counts once).
- `column`: from 1, in Unicode scalar values, not bytes; a leading
  byte-order mark is not counted.
- `UnexpectedEnd` is at the end of the input, except when the input ends
  inside a string, block comment or escape sequence: then it points at
  where that construct starts, and `expected` says so. `InputTooLarge`
  points at the character that holds the first byte past the limit.

`Limits`, each checked before the memory it guards is allocated (override
fields with `Limits { max_input_bytes: n, ..Limits::DEFAULT }`):

| Field | Default | Bounds |
| :- | :- | :- |
| `max_input_bytes` | 64 MiB | Input length; checked first (in `parse_bytes`, before UTF-8 validation) |
| `max_depth` | 128 | Array and object nesting (a scalar is depth 0, `[[1]]` is 2) |
| `max_string_bytes` | 16 MiB | One string or key, in UTF-8 bytes after escapes are decoded |
| `max_number_bytes` | 1,024 | One number's text (sign, digits, point, exponent) |
| `max_entries` | 1,000,000 | Elements or members of one array or object, not of the whole document |

Memory and stack:

- The parser keeps its own stack on the heap and takes a failed tree apart
  without recursing, so no depth limit can overflow the thread's stack
  while parsing. Dropping, cloning, comparing, `Debug` and writing a `Value`
  do recurse once per level, so keep `max_depth` in the hundreds.
- A parsed tree takes at most 16 bytes of heap per byte of text, plus a
  constant and a little working memory while parsing: a `Value` is 32 bytes
  and needs at least 2 bytes of text (`0,`), and containers are allocated
  at exactly their size. With glibc's per-allocation overhead, the worst
  documents measured (`[[0]],` repeated) grow the process by about 23 times
  their text; typical ones take 2 to 4 times (`cargo metadata` about 3). At
  the default `max_input_bytes` the tree is capped at 1 GiB, about 1.5 GiB
  with glibc.

Writing:

- Both writers emit strict JSON (no comments, no trailing commas) with
  members in stored order, repeated names included, and escape only `"`,
  `\` and U+0000 to U+001F. Integers are written as their digits; floats as
  the shortest form that reads back as the same `f64`, always with a `.` or
  an exponent (`1e3` is written `1000.0`).
- Pretty output indents two spaces per level, writes `": "` after names,
  keeps empty containers as `[]` and `{}`, and has no trailing newline.
- Output reads back as an equal value if it fits the `Limits` it is read
  with; it can be longer than the text it was parsed from.
- Pretty output of a value nested `d` deep is at most `2d + 2` times its
  compact size. Values shaped for it (`[[[0]]],` repeated) reach about 236
  times at depth 128, so a 64 MiB document can pretty-print to about 15 GiB.
  Bound the depth or compact size of an outside value before pretty-printing
  it.

### `toml`

`parse(&str, Limits)` and `parse_bytes(&[u8], Limits)` return the root
`Table` of a TOML 1.1 document (ADR-0026). The module documentation in
`crates/codec/src/toml.rs` is authoritative; this is its summary.
`Document` builds on the parser to edit a document and keep the rest of
its text, comments included (see "The document model" below). The
compliance cases are toml-test v2.2.0's 1.1 list, vendored in
`crates/codec/tests/toml-test/` (see "Tests" below).

All of TOML 1.1.0 is accepted: everything 1.0.0 has, which 1.1 only
relaxes, plus line breaks, comments and a trailing comma in inline tables,
the `\xHH` and `\e` escapes, and times without seconds. There is no strict
1.0 mode. Where the specification leaves room:

- **Encoding:** the input must be UTF-8. `parse_bytes` rejects anything
  else (`InvalidUtf8`, at the first bad byte) and never repairs it.
- **Byte-order mark:** a leading U+FEFF is skipped. Anywhere else outside a
  string it is an error; inside a string or comment it is an ordinary
  character.
- **Lines** end at LF or CR LF; a CR alone is an error wherever it is
  (`BareCarriageReturn`), strings and comments included. Whitespace is space
  and tab.
- **Multi-line strings** turn each CR LF into LF, so a file's values do not
  depend on its line endings; an escaped `\r\n` stays. Raw control
  characters other than tab and line breaks are rejected in strings and
  comments (`ControlCharacter`). A line break ends a comment, is part of a
  multi-line string, and in a single-line string is an
  `UnexpectedCharacter`, since that string must close on its line. Escapes
  must be Unicode scalar values (`InvalidUnicodeEscape`).
- **Integers** are `i64`; one out of range is an error in any base
  (`IntegerOutOfRange`).
- **Floats** are `f64`, read correctly rounded with `str::parse` once the
  underscores are removed. Too large (`1e400`) is `FloatOutOfRange`, not
  infinity, which is written `inf`; too small becomes zero. Signed zeros keep
  their sign, and `-nan` keeps its sign bit.
- **Date-times** are a `Datetime` of TOML's four kinds (offset date-time,
  local date-time, local date, local time), with every field checked: days
  per month with Gregorian leap years, hours 00 to 23, minutes 00 to 59,
  seconds 00 to 60 (a leap second in any minute), offsets of 00:00 to 23:59
  either way. A fraction of a second keeps nine digits, as nanoseconds; the
  rest are dropped, not rounded. Left-out seconds are zero. Not recorded:
  whether seconds were written, `Z` or `z`, and `T`, `t` or a space between
  date and time (the span has the text). `Z` and `+00:00` stay apart.
- **Keys** compare exactly (decoded, case-sensitive, no normalization).
  Bare keys are ASCII letters, digits, `-` and `_`, and are strings even
  when they look like numbers.
- **Definitions:** no key or table is defined twice; dotted keys cannot add
  to a table a header defined, and a header cannot define a table that dotted
  keys or an inline table defined; inline tables and arrays written as
  values are complete as written; `[[header]]` adds only to an array of
  tables, and `[header]` cannot name one.

The value tree:

- A `Table` keeps its entries, each a `Key` and a `Value`, in document order
  (for a table defined in pieces, the order its keys first appear in), and
  finds a key in constant time: past 8 entries it keeps an index of their
  positions by the hash of their names (`std`'s randomly keyed SipHash),
  which takes 8 to 16 bytes an entry and holds no copy of the names.
  `Table::kind` says how it was defined: `Root`, `Header`, `ArrayHeader` (an
  element of an array of tables), `Implicit` (only ever a header's prefix),
  `Dotted` or `Inline`.
- A `Value` is a `ValueKind` (`String`, `Integer(i64)`, `Float(f64)`,
  `Boolean`, `Datetime`, `Array`, `Table`) and a `Span`. An `Array` is
  written as a value or is an array of tables (`is_array_of_tables`).
- Spans are byte ranges in the input as given, a leading byte-order mark
  counted. A key spans its text, quotes included; a scalar its literal; an
  array `[` to `]` and an inline table `{` to `}`; a header's table its
  header; an element of an array of tables its own `[[...]]` and the array
  the first one. A table created implicitly spans what created it, the
  whole header or dotted key; one defined later takes the span of what
  defined it, and its key the name there.

Errors: every failure is `CodecError::Toml { offset, line, column, kind }`
with a `toml::ErrorKind`, and the parser never panics. `offset`, `line`
and `column` follow the conventions of `json` above (a byte-order mark
counts in the offset, not the column; lines end at LF, so CR LF is one;
columns count Unicode scalar values). `UnexpectedEnd` is at the end of the
input, except inside a string or escape, where it points at where that
starts. Messages never quote the input beyond the one character found.

| Kinds | What they report |
| :- | :- |
| `UnexpectedEnd`, `UnexpectedCharacter` | The text ends, or the character `found` is wrong, where `expected` was needed; this includes a value that starts with `_` or with a letter other than `t`, `f`, `i` and `n`, and a line break in a single-line string |
| `InvalidUtf8`, `ControlCharacter`, `BareCarriageReturn` | Bytes that are not UTF-8; a raw control character other than tab and line breaks, in a string or comment; a CR that is not followed by LF, anywhere |
| `InvalidLiteral`, `InvalidEscape`, `InvalidUnicodeEscape`, `MultilineKey` | A word that starts like `true`, `false`, `inf` or `nan` and is not one (`tru`, `nope`); escapes; a multi-line string as a key |
| `LeadingZero`, `MisplacedUnderscore`, `IntegerOutOfRange`, `FloatOutOfRange` | Numbers; an underscore that is not between two digits (`1_`, `+_1`, `0x_1`) |
| `InvalidDatetime` | A date or time field out of range; `expected` gives the range |
| `DuplicateKey`, `DuplicateTable` | A key or table defined twice |
| `NotATable`, `NotAnArrayOfTables` | A dotted key or header through, or `[[...]]` onto, the wrong kind of value; `found` names it |
| `ExtendsInlineTable`, `ExtendsDefinedTable` | Adding to an inline table after it closes, or with dotted keys to a header's table |
| `InputTooLarge`, `TooDeep`, `StringTooLong`, `NumberTooLong`, `TooManyEntries` | A `Limits` field |

`Limits`, each checked before the memory it guards is allocated, with the
defaults of `json` above:

| Field | Default | Bounds |
| :- | :- | :- |
| `max_input_bytes` | 64 MiB | Input length; checked first (in `parse_bytes`, before UTF-8 validation) |
| `max_depth` | 128 | Tables and arrays between the root and a value, however written: `a = [[1]]`, `a.b.c = 1`, `[a.b]` and `[[a]]` (an array and its element) are each 2 |
| `max_string_bytes` | 16 MiB | One string, or one part of a key, in UTF-8 bytes after escapes are decoded |
| `max_number_bytes` | 1,024 | One number's or date-time's text |
| `max_entries` | 1,000,000 | Entries of one table or array, an array of tables included |

Memory and stack:

- The parser keeps its own stack on the heap and takes a failed tree apart
  without recursing; a key's parts are checked against the depth as they
  are read, so a 10,000-part key stops at the first part too deep (the
  129th, at the top level). Dropping, cloning, comparing and `Debug` of a
  `Value` recurse once per level, so keep `max_depth` in the hundreds.
- A tree takes more memory than JSON's, since every key and value carries
  its span: a value is 56 bytes, a table's entry 96, and an index 8 to 16
  bytes an entry. Once a parse is over, every table, array, string and key
  is at exactly its size. The densest documents are chains of one-entry
  tables (`a.b.b.b… = 0`, `[a.b.b…]`), at 97 bytes of heap for each 2-byte
  `.b`, so a tree holds at most about 49 bytes of heap per byte of text; a
  unit test sums the tree's allocations for such documents and checks it.
- With glibc's overhead (measured as the growth of the process's resident
  set, in a release build): chains of one-entry tables about 71 times their
  text; small tables of one-letter keys (`[[a]]` or `[t]` with nine keys,
  arrays of nine-key inline tables) about 36 to 38; arrays of scalars 29;
  a key or empty header on each line 20; `Cargo.lock` 7. At the default
  `max_input_bytes` a tree can take about 3 GiB of heap, about 4.5 GiB with
  glibc, so lower it to read TOML from an untrusted source.
- Parsing takes linear time. Measured (this machine, not the bench
  harness): 100,000 keys in one table parse in 0.23 s in a debug build and
  0.03 s in release, and 10,000 sibling tables in 0.026 s and 0.004 s.

#### The document model: `toml::Document`

`Document` holds a TOML document's text, its parsed root `Table` and the
`Limits` it was read with. A caller reads values through the tree, changes
or adds them with `set`, and takes the text back. If nothing was edited, the
text is the input byte for byte. After edits, only the bytes of the changed
value, or of the added entry or table, are new (ADR-0013, ADR-0031). The
rustdoc in `crates/codec/src/toml.rs` ("Editing") is authoritative.

```rust
#[derive(Clone, Debug)]
pub struct Document { /* text: String, root: Table, limits: Limits */ }

impl Document {
    /// Parses as `toml::parse` does and keeps a copy of the text. `limits` also bound every later edit.
    pub fn parse(text: &str, limits: Limits) -> Result<Self, CodecError>;
    /// The same for bytes, which must be UTF-8, as `toml::parse_bytes` reads them.
    pub fn parse_bytes(bytes: &[u8], limits: Limits) -> Result<Self, CodecError>;
    /// The text: the input until an edit, then the input with only edited bytes changed.
    pub fn as_str(&self) -> &str;
    /// The text, consuming the document.
    pub fn into_string(self) -> String;
    /// The root table. Its spans index `as_str()`.
    pub fn root(&self) -> &Table;
    /// The value at `path`. None for an empty path, a missing step, or a Key step on an array of tables.
    pub fn get(&self, path: &[Step<'_>]) -> Option<&Value>;
    /// Makes the value at `path` equal to `value`: replaces it, or adds it with any missing tables.
    /// Does nothing if it already holds equal data. On error the document is unchanged.
    pub fn set(&mut self, path: &[Step<'_>], value: &ValueKind) -> Result<(), CodecError>;
}

/// One step of a path from the root table.
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum Step<'a> {
    /// The entry with this name, decoded and compared exactly, as `Table::get` compares.
    Key(&'a str),
    /// The element at this index, from 0, of an array written as a value or of an array of tables.
    Index(usize),
}
impl<'a> From<&'a str> for Step<'a> { /* Step::Key */ }
impl From<usize> for Step<'_> { /* Step::Index */ }
```

- **Invariant:** `root()` always equals `toml::parse(as_str(), limits)`.
  Neither field is ever exposed mutably.
- **Spans after an edit:** every edit makes a new tree, so spans from before
  it are stale. The borrow checker stops a caller from holding a `&Value`
  across `set`.
- **Batches:** to make several edits atomic, clone the `Document`, edit the
  clone, and keep it only if every edit succeeds.
- **New files:** an empty document is `Document::parse("", limits)`.

**Paths.**

- A `Key` step needs a table; an `Index` step needs an array.
- An array of tables is always indexed explicitly. A `Key` step on one is
  `NotATable { found: "an array of tables" }`, and the editor never picks
  the last element for the caller.
- A path is by structure, not spelling: `editor.font-size = 14` at the root,
  `[editor]` with `font-size = 14`, and `editor = { font-size = 14 }` are
  all `["editor", "font-size"]`.

**Building values.**

- `Value: From<ValueKind>` gives span `0..0`.
- `Array::new(Vec<Value>)` builds an array written as a value.
- `Table::new_inline()` builds an empty table of kind `Inline`.
- `Table::insert(name, value: impl Into<Value>) -> Option<Value>` replaces
  an existing entry in place, or appends a new one.
- The writer ignores the spans and the `TableKind` of a value built in code.
- A value read from another document, such as the defaults, is passed as
  `&value.kind`, without a clone.

**Setting a value that exists.**

- If the value at the path holds the same data, nothing changes. This makes
  a "save every setting" pass byte for byte when nothing changed, and keeps
  `0x10`, `1_000`, `'lit'` and `07:30` as written.
- "Same data" means:
  - same kind and value, spans and table kinds ignored;
  - floats compared by bits, with any two NaNs of one sign equal;
  - arrays compared in order, with the array-of-tables flag ignored;
  - tables compared entry by entry in order.
- Otherwise, if the value is a scalar, an array written as a value, or an
  inline table (at a key or at an index of an array), exactly the bytes of
  its span are replaced with created text.
  - The key, the spaces, the comment after the value and the line break
    stay.
  - A multi-line string or array, or an inline table laid over several lines
    (TOML 1.1), is replaced whole by one line of TOML 1.0, and comments
    inside it go with it. This is the accepted reading of ADR-0031: the
    bytes an edit changes are the whole value's.
  - To keep such a layout, set its entries or elements instead. Those edits
    replace only their own spans, so the 1.1 layout around them stays
    (ADR-0031).
  - The type may change.
- Otherwise the edit is refused with `NotReplaceable`, because the value's
  text is spread over lines or sections. That covers a table defined by a
  header, an element of an array of tables, a table made by a header's
  prefix (`Implicit`), a table made by dotted keys, and an array of tables.

**Adding a value.** The walk stops at N, the deepest table on the path that
exists. After it come the missing tables t1…tm (m ≥ 0) and the final key k.
An `Index` step among them is `MissingArray`.

Terms used in the rules:

- **c0:** 3 if the text starts with U+FEFF, otherwise 0. No edit writes
  before c0. The content is the text from c0.
- **nl:** CR LF if the text's first line break is CR LF, otherwise LF.
- **le(x):** the line end after offset x. Skip spaces and tabs, then a `#`
  comment, then the LF or CR LF; or stop at the end of the text.
- **Leaves of T:** T's entries whose value is a scalar, an array written as
  a value or an inline table, plus, recursively, the leaves of T's Dotted
  children. Never through Header, ArrayHeader or Implicit tables, nor
  through arrays of tables. A Dotted table's leaves are all in the section
  of its nearest non-Dotted ancestor, which is Root, Header, ArrayHeader or
  Inline.
- **Last leaf:** the leaf with the largest span end. Its key line is the
  line where its key's span starts.
- **Section end** of a Root, Header or ArrayHeader table: le(the end of its
  last leaf). With no leaves, le(its header's span end), or for Root the
  root point.
- **Root point:**
  - With headers: the line start of the first header (the smallest span
    start of any Header table or ArrayHeader element), moved up over the
    comment lines directly above it. Blank lines stop the move. Before the
    first header there are then only blank and comment lines, so this scan
    is exact.
  - With no header: the end of the text.
- **Subtree end of N:** le(x), where x is the largest of the span ends of
  every leaf of every non-inline table in N's subtree, and of every Header
  and ArrayHeader header in it, N's own included. The walk enters tables of
  every kind except Inline, and arrays of tables, but not arrays written as
  values. If there is nothing (a document with no keys and no headers), it
  is the end of the text.
- **Indent:** the leading spaces and tabs of the last leaf's key line. There
  is none after a header line or at the root point.
- **Key text:** the names written as keys and joined by `.`. The **key
  line** is `indent + key text + " = " + value`.

Where an added value goes:

| N | m | Inserted | Where |
| :- | :- | :- | :- |
| Root with leaves; Header; ArrayHeader element | 0 | key line `k = v` | at N's section end: N's own section, so `[[a]]` element 0 of 3 gets it before the second `[[a]]` |
| Root without leaves | 0 | key line, then a blank line | at the root point |
| Dotted D in a section | any | key line `p.t1….tm.k = v`, where p is the names from the section's table (exclusive) down to D | at le(the end of D's last leaf), with that leaf's indent |
| Inline C, or Dotted D inside C, with a leaf | any | `, q.t1….tm.k = v`, where q is the names from C (exclusive) down to N | right after the span end of N's last leaf, before any comma, comment or line break that follows it |
| Inline C, empty | any | ` t1….tm.k = v`, plus a space if `}` follows `{` directly | right after `{`: `{}` becomes `{ k = v }`, `{\n}` becomes `{ k = v\n}` |
| Implicit | 0 | header block `[path(N)]`, then `k = v` (N becomes Header) | at N's subtree end |
| Root, Header, ArrayHeader, Implicit | ≥ 1 | header block `[path(N).t1….tm]`, then `k = v` (t1…tm−1 become implicit) | at N's subtree end |

- **path(N)** is the `Key` steps from the root to N, with the `Index` steps
  left out. A header names the last element of each array of tables on its
  path.
  - Every section in element i's subtree lies before element i+1's
    `[[...]]`, so a header placed at element i's subtree end names element
    i.
  - Only blank and comment lines lie between a subtree end and the next
    header, so a new header takes no existing keys.
- **No forbidden extensions:** a header is never written where dotted keys
  or an inline table made a table, and a dotted key is never written into a
  table a header defined. So `ExtendsInlineTable`, `ExtendsDefinedTable` and
  `DuplicateTable` cannot arise.
- **Line insertion** of lines at P (always a line start or the end of the
  text), with the flags blank_before (header blocks) and blank_after
  (header blocks, and a root key at the root point):
  - **Empty content** (`""` or a BOM alone): each line followed by nl,
    written at c0.
  - **End of a text with no final line break:** first nl, then nl again if
    blank_before is set and the last line is not blank, then the lines
    joined by nl and no final nl. A file that had no final newline still has
    none.
  - **Otherwise:** nl first, if blank_before is set, P > c0 and the line
    before P is not blank; then each line followed by nl; then nl, if
    blank_after is set, P is not the end of the text and the line at P is
    not blank.
- **Neighbouring text:** comments and blank lines after the line that a new
  key line follows stay below the new line, and comments attached to the
  next header stay attached to it.

**Created text** is TOML 1.0 (ADR-0031) and fits on one line:

| Kind | Written |
| :- | :- |
| Key part | Bare when it is non-empty and only ASCII letters, digits, `-` and `_` (so `3`, `true` and `tab-size` stay bare); otherwise quoted by the string rule. Parts are joined with `.` and no spaces. A header is `[a.b]`; `[[...]]` is never written |
| String | A literal `'…'` when the text holds a `\` or a `"`, no `'`, and no U+0000–U+001F or U+007F (`'C:\Users\me'`). Otherwise a basic `"…"`: `\"`, `\\`, `\b \t \n \f \r`, and `\uXXXX` with uppercase hex for every other control character and DEL (`\u001B`); everything else raw. Never multi-line, never `\e`, `\xHH` or `\U` |
| Integer | Decimal, `-` for negatives, no `+`, underscores or base prefix |
| Float | Finite: `json::Number::from_f64(v)`'s `Display`. That is the shortest digits that read back as the same `f64`, in exponent form when the magnitude is not 0 and outside [1e-5, 1e16) (`1e16`, `5e-324`, `1.5e300`), with `.0` on whole numbers (`3.0`, `-0.0`). Then `inf` and `-inf`; NaN is `nan` or `-nan` by its sign bit, and its payload is not kept. Every finite value reads back bit for bit |
| Boolean | `true`, `false` |
| Date-time | Checked first, because a value built in code is not: year 0–9999, month 1–12, a day the month has, hour ≤ 23, minute ≤ 59, second ≤ 60, nanosecond ≤ 999,999,999, offset within ±1439 minutes. Then `Datetime`'s `Display`: `T`, the seconds always written, the fraction without trailing zeros, `Z` or `±HH:MM` (`+00:00` stays apart from `Z`). A time parsed from `07:32` and then changed is written with `:00` seconds |
| Array | `[a, b]` or `[]`, with no trailing comma. Tables in it are inline. An array of tables passed as a value is written as an array of inline tables |
| Table value | `{ k = v, k2 = v2 }` or `{}`, entries in order, nested tables inline (never dotted keys). No comment, line break or trailing comma |

**Errors.**

- `Document::parse` and `Document::parse_bytes` fail exactly as
  `toml::parse` and `toml::parse_bytes` do, with `CodecError::Toml`.
- `set` fails with `CodecError::TomlEdit { step, kind: toml::EditErrorKind }`,
  and the document is then unchanged.
- `step` is the index of the path step the problem concerns: the step that
  could not be taken, `path.len() - 1` for the target, or `path.len()` for
  the edit as a whole.
- Messages never quote keys or text.

| `EditErrorKind` | When | `step` |
| :- | :- | :- |
| `EmptyPath` | The path has no steps | 0 |
| `NotATable { found }` | A `Key` step on a scalar, an array written as a value, or an array of tables | that step |
| `NotAnArray { found }` | An `Index` step on something that is not an array | that step |
| `IndexOutOfRange { len }` | An `Index` step past the end; edits never add elements | that step |
| `MissingArray` | An `Index` step after a key that does not exist; edits create tables only | that `Index` step |
| `NotReplaceable { found }` | The target is a table under a header, an element of an array of tables, a table made by a header's prefix, a table made by dotted keys, or an array of tables, and the data differs | `path.len() - 1` |
| `InvalidDatetime { expected }` | A date-time in the new value has a field out of range (`expected` as in `ErrorKind::InvalidDatetime`) | `path.len() - 1` |
| `TooLarge { limit }` | The new text would be longer than `max_input_bytes`; this is found before anything is allocated, and the writer stops at the room left | `path.len()` |
| `Limit(ErrorKind)` | The new value nests deeper than `max_depth` (`TooDeep`, checked before writing), or the new text breaks a limit when it is read again (`TooDeep`, `StringTooLong`, `NumberTooLong`, `TooManyEntries`) | `path.len() - 1` before writing, `path.len()` when read again |
| `Unverified { reason }` | The new text did not parse, or its data is not the old data plus exactly this edit. This is a bug in the document model, and the edit is refused rather than corrupting the file | `path.len()` |

**Verification.** Every edit except a no-op works in local variables, then
commits:

1. Plan one splice: a range of the old text, empty for an insertion, and the
   created text.
2. Check the new length with checked arithmetic.
3. Build the new text from `get` slices.
4. Parse it with the document's `Limits`.
5. Walk the old and new trees together along the path:
   - At each table on the path, the new table has the old table's entries,
     in the same order and with the same data, apart from the stepped entry,
     which may be new and may sit at any position.
   - At each array, the lengths and the array-of-tables flag match, and
     every item except the indexed one has the same data.
   - Each created table holds only the next step.
   - The value at the path has the same data as `value`.
6. Only then assign the text and the tree.

Text outside the splice is unchanged by construction. The cost is one parse
and one tree walk per edit, linear in the document's size, with two trees
in memory briefly. A settings file of a few KB takes microseconds.

**Limits and untrusted input.**

- A document may come from an untrusted workspace, and nothing panics on
  it: all text access uses `get` and checked arithmetic; every walk keeps an
  explicit stack; and the writer recurses only after the value's depth
  (measured without recursion) is known to be within `max_depth`.
- Sizes stay bounded by the stored `Limits`.
- Because an edit briefly holds two trees, read workspace and user settings
  with a lower `max_input_bytes`, for example 1 MiB (see `Limits`).

**Not supported** (later tasks add them when a caller needs them):

- Removing keys, tables or elements; renaming, reordering or moving
  entries. A "reset to default" can set the default value but cannot remove
  the key.
- Appending to an array, or adding a `[[...]]` element. The rule is ready
  for later: after the last element's subtree end.
- Replacing a table under a header, a dotted or implicit table, or an array
  of tables as a whole. Set its entries instead.
- Writing a table value under a header: a table passed to `set` is always
  written inline. Set its leaves to get a header.
- Multi-line created text, and keeping a changed value's spelling (base,
  underscores, quote style, left-out seconds, `t`, `z`).
- A comment API, detecting 1.1 syntax, reformatting, and applying several
  edits under one re-parse.
- Settings semantics (layers, validation, version keys, migrations) belong
  to M4.7. File I/O belongs to `text::file`, called on workers.

Example (also the crate README's doc test, and the module documentation's):

```rust
use tidepool_codec::Limits;
use tidepool_codec::toml::{Document, ValueKind};

let limits = Limits { max_input_bytes: 1024 * 1024, ..Limits::DEFAULT };
let mut doc = Document::parse("# Mine\n[editor]\nfont-size = 14 # big\n", limits)?;
doc.set(&["editor".into(), "tab-size".into()], &ValueKind::Integer(4))?;
doc.set(&["editor".into(), "font-size".into()], &ValueKind::Integer(16))?;
doc.set(&["theme".into(), "name".into()], &ValueKind::String("tidepool-dark".into()))?;
assert_eq!(
    doc.as_str(),
    "# Mine\n[editor]\nfont-size = 16 # big\ntab-size = 4\n\n[theme]\nname = \"tidepool-dark\"\n"
);
```

## `tidepool-regex`

- Parser → NFA → Pike VM simulation; linear time in input length for every
  pattern. No backreferences or lookaround (documented; vim mode reports
  the difference).
- Unicode classes for general categories and scripts used by language
  packs; case-insensitive matching with simple case folding.
- Literal prefix acceleration for search.

## Tests

- `text`:
  - property tests against a `String` model (≥ 10,000 random edit
    sequences, with tiny chunks in unit tests and real sizes in integration
    tests);
  - conversion round-trips at every position in every unit (tiny chunks),
    and near every seam and sampled elsewhere at real sizes;
  - grapheme conformance with every case of `GraphemeBreakTest.txt`, also
    split across chunks;
  - a reference reading of the rules, and the Unicode version test;
  - undo, redo and jumps against a model that keeps every revision's text.
    The model covers random commits with every grouping, long command
    groups, branches, saved markers and errors, with the apply path forced
    at random. The tests check that:
    - undo restores the first text exactly;
    - every revision is reachable with its exact text;
    - every refused operation changes nothing;
  - change-set laws and mapping against a `String` model, and selection
    invariants after every operation;
  - decoding random bytes biased toward near-valid UTF-8 and UTF-16, against
    `String::from_utf8_lossy` and `char::decode_utf16`: lossless for every
    input, the same however it is split, and valid input re-encodes to
    itself;
  - file round-trips byte for byte: UTF-8 with and without a BOM, UTF-16 LE
    and BE, LF, CR LF, lone CR, mixed endings, no trailing newline, the
    empty file; invalid files load read-only; a simulated crash between
    write and rename and a failed write leave the original; refused saves
    change nothing; the large-file threshold; on Unix, modes and links.
- `codec`: RFC 8259 JSON cases, toml-test's TOML 1.1 cases, ZIP files
  produced by the `zip` command-line tool and by Android and Apple tools,
  hand-made vectors for inflate edge cases (stored, fixed and dynamic
  blocks, back-references at the window edge); every module is a fuzz
  target with a seed corpus.
- `regex`: conformance table; pathological patterns (`(a*)*b` on long
  inputs) finish in linear time.
